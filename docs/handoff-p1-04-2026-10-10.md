## Current implementation

P1-04 now has the following headless code. The database schema remains
version 1; no history table, collector or browser UI has been added.

- `atlas-store/src/location.rs` and `engine/session.rs` keep exclusive session
  ownership until all connections close. `atlas-platform/src/storage/session.rs`
  implements the native gate and external running/clean record. Missing or
  malformed evidence triggers conservative checking; failures and fallback
  destruction do not attempt a clean write. A failed marker flush is returned
  and poisons that control; its eventual persistence is uncertain.
- `atlas-store/src/backup.rs` queues maintenance on the existing writer,
  makes idle daily `VACUUM INTO` snapshots, validates integrity, foreign keys,
  exact schema and model records read-only, then publishes and retains seven
  valid copies. The new published candidate must survive revalidation before
  rotation. Failed output is preserved, errors surface, and a failed attempt
  remains due in the current session. Ordinary not-due checks use a cached
  timestamp; startup rediscovers validated completion evidence.
- `atlas-platform/src/storage/backup.rs` owns fixed-name guarded bundles,
  bounded completion markers and identity-checked nonrecursive removal.
  Each archive operation checks registered sync roots once, including the
  archive and bundle identities. Later registration remains the documented
  limitation; retained filesystem identities are rechecked throughout.
- `atlas-platform/src/storage/recovery.rs` and `recovery/resume.rs` expose
  `offer_recovery(...).confirm()`. The dated offer owns the exact source and
  primary identities. Recovery copies and validates a stage, flushes an
  intent before moves, preserves the primary and sidecars together, installs
  without replacement and validates again. Known interruption states produce
  a renewed confirmation offer for that same source; ambiguous identities or
  damaged intent remain refused. The original backup is never moved.
- `atlas-store/src/deletion.rs` defines D47's pure journal codec and replay
  contract: paired request/completion records, damage detection, ordered
  generations and explicit pending-clear refusal. It performs no filesystem
  persistence. Schema-1 recovery refuses any nonzero or pending deletion
  state. P1-27 must persist the external journal/generation barrier and
  implement all actual clearing/replay participants before shipping history
  clearing. Never replace that refusal with silent acceptance.
