## P1-05 implementation and evidence

`crates/atlas-search` now contains a derived metadata catalogue with typed
targets, incremental upsert/removal, mutation generations and a complete
rank/count/highlight query. It depends on `atlas-core` for existing tab and
saved-page identities. History and command IDs are opaque nonzero integers;
there is no history collector, registry, plugin runtime, full text or UI.

The caller supplies the search policy. Saved/live records remain distinct;
P1-31 will settle their visible presentation. Original title and address
strings are matched independently. Scope counts precede filtering and limits.
Content and usage diagnostic formatting is redacted. The crate README
defines matching limitations, scores, ranges and input bounds.

The exact new external dependency is `frizbee =0.13.0`, defaults disabled,
with `std` and `safe_read`. Its MIT licence, source identity, maintenance and
published advisory record were checked before addition. It adds no active
transitive dependency; existing package versions are unchanged. The lockfile
records inactive optional serde/derive edges, not feature activation.
See `docs/dependency-audit.md`. Do not remove `safe_read` to improve timings.

`crates/xtask/src/benchmark.rs` adds `cargo xtask bench`: 100,000 synthetic
records, 26 query cases, five warmup passes and 40 interleaved measured
passes. It measures complete result construction, including rank/counts and
highlights. JSON on stdout retains all samples, per-case medians/p95/maxima
and the overall maximum. It validates results outside the timed interval.

worst."** Apply that threshold independently to every query case; do not
average slow cases into easier ones. Three fresh-process runs are the
repeatability protocol. Benchmark top-50 and typo settings are explicit
