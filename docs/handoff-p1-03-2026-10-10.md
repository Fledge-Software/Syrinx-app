## What P1-03 contains

`atlas-core` now exports owned snapshot types and validates identities,
selection, saved/live associations, ordering and allocation watermarks.
Restoration keeps retired identities retired and resets the in-memory
20-entry closed-tab history. Saved destinations remain separate from live
navigation metadata (D43).

`atlas-store` adds bundled SQLite and transactional migrations. One writer
thread accepts a bounded queue; two separately locked readers observe
consistent committed snapshots. `Store::load` returns a revision and
snapshot; `Store::save(expected_revision, snapshot)` rejects stale writes
and regressing watermarks before atomically replacing state. Full `u64`
identities/counters use eight-byte BLOBs. Foreign, future, altered and
malformed current databases are refused. Errors retain structural values,
not paths, SQL text or record content. `Store` blocks and belongs on host
worker threads, never the future UI event thread; call `shutdown` to observe
close errors.

The filesystem-only `atlas-platform` implements `DirectoryLease` from the
store. It discovers local app data only when explicitly called, refuses
registered sync roots, nonlocal drives, reparse points and hardlinked
database/sidecar files, and retains checked ancestor/main-file handles until
all SQLite connections close. Test code uses explicit disposable locations;
the console application still opens no production database. Full Windows
revalidation runs at connection lifecycle boundaries, not every read/save.

New/modified source areas are `crates/atlas-core/src/tabs/snapshot.rs`, core
exports, all of `crates/atlas-store` and `crates/atlas-platform`, and workspace
manifests/lockfile. Supporting changes are in `AGENTS.md`, local-development
and dependency-audit docs, the storage-path preflight, traps, both plan-1
maps/status records, and this handoff. The source is committed; completion
documentation follows without changing the tested code.
